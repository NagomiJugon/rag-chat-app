# URLの取り込みとベクトル検索の詳細

基本的な使い方は [README](../README.md) を参照してください。取得時のルールは [開発ポリシー](policy.md) にあります。

## 取り込みと検索の動作

- 指定した単一HTMLページのテキストを分割・埋め込みし、ChromaDBに保存します。リンク先を自動巡回せず、JavaScriptの実行やログインも行いません。
- 検索結果には関連チャンクと、リダイレクト後の取得元URLが表示されます。検索はLLMによる回答生成や既存チャット画面にはまだ接続されていません。
- 同じ最終URLを再取り込みすると、そのURLのチャンクを更新し、不要になった古いチャンクを削除します。更新途中に失敗した場合は同じURLを再実行してください。
- データとモデルはDockerボリュームに保存されるため、通常の `docker compose down` や再ビルド後も残ります。`docker compose down -v` はこれらを含むボリュームを削除します。
- 既定設定ではローカルのOllamaで埋め込みを実行し、ページ本文や検索語を外部の埋め込みAPIに送信しません。`OLLAMA_BASE_URL` を変更する場合は接続先にこれらのデータが送られます。

## 環境変数

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `EMBEDDING_MODEL` | `bge-m3` | Ollamaの埋め込みモデル。利用前に `ollama pull` が必要です。既存のコレクションと異なるモデルは拒否されるため、変更する場合は別のデータ保存先で新規に取り込んでください。 |
| `CHROMA_DIR` | `./chroma_data`（Docker内は `/data/chroma`） | ChromaDBの保存先 |
| `OLLAMA_BASE_URL` | `http://localhost:11434`（Docker内は `http://ollama:11434`） | OllamaのURL |

## 取得処理の安全動作

- 各オリジンのrobots.txtを取得して確認し、リダイレクトのたびに移動先も確認します。
- robots.txtが取得・解釈できない場合、robots.txtがリダイレクトされた場合、未対応の `Visit-time` が指定されている場合は安全側に停止します。
- `Retry-After` を受け取った場合も再試行せず停止します。指定された時間以降に再実行してください。
- 同一のChromaDB保存先を使う取り込みコマンドは直列化されます。ホストごとに最低1秒、robots.txtで `Crawl-delay` や `Request-rate` が指定された場合はより長い間隔を空けます。
- 別の保存先や別のツールから同時にアクセスしないでください。
